## 3. What the AI added that I never asked for

- Chose a full tech stack (Next.js + TypeScript) and built a web UI instead of a
  simple script, even though the original prompt only asked for a program that
  "prints" results
- Added an adjustable pass threshold slider (default 50) — never requested
- Added a grade distribution histogram chart — never requested
- Added a per-mark results table with grade letters (A, B, F, etc.) — never requested
- Added invalid-entry detection with a specific 0–100 range — I never specified
  what counts as valid, yet it matched Part 1's rule almost exactly
- Added a "Load Sample Data" button and a "Copy Results" button — never requested

## 4. What the AI got wrong or silently skipped

- The class average was displayed with only 1 decimal place (e.g. 67.0) instead
  of the required 2 decimals (e.g. 67.00), across all three cases with valid data
  (A, B, C). Input: `85, 23, 45, 90, 92` → expected avg `67.00`, actual `67.0`.

## 5. The defect I asked Rocket to fix

**Prompt I used:**
The class average should be displayed with 2 decimal places (e.g. 67.00),
not 1 decimal place (e.g. 67.0). Please fix this.

**Result:** (fixed / partly fixed / broke something else)
fixed — re-tested cases A, B, C and all now show 2 decimal places
correctly (67.00, 71.60, 20.00). No other values (total, highest, lowest,
pass rate) were affected by the fix.

**What this tells me:**
Rocket can accurately fix a narrowly-scoped, clearly
described bug without introducing regressions — but only because I found and
described the bug precisely myself first.

Rocket really did save time on the parts I don't enjoy — building a UI,
connecting everything together, adding nice touches like a chart and a
results table. In about 5 minutes I had a working app with a full interface.
That would have taken me much longer to build by hand. The clarifying
questions it asked before building were also helpful — they made me think
about who would use the tool before any code was written, something I
sometimes skip when coding on my own.

Where it cost me time was checking the work, not building it. The app
*looked* right at first, but the average was cut to 1 decimal place instead
of 2 in every test with real data. If I hadn't run the same four test cases
from Part 1, I might not have noticed — the numbers looked close enough at a
glance. Rocket also added things I never asked for, like a threshold slider,
sample data, and a chart. That's extra stuff I now have to check or trust.

I would put my name on the **manual Python version** without hesitation. I
wrote every line myself, I understand why it works, and I could explain it
to anyone. I would not put my name on the Rocket app yet — I only tested it
through the interface, I never actually read its code, so I can't fully
vouch for it.

That's the main lesson: a human engineer still has to define what "correct"
actually means, write test cases that catch hidden bugs, and read or check
the generated code before trusting it. AI can build something that runs —
but it can't decide what counts as right for you.
